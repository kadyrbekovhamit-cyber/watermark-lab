# Watermark Lab

Локальный исследовательский инструмент для проверки **известного профиля открытой схемы SynthID-Text**. Разобран публичный алгоритм; секретный ключ Claude не восстановлен. Проверка произвольного текста на происхождение из Claude **пока недоступна**.

По [пояснению Anthropic](https://www.anthropic.com/news/claude-text-watermark), Claude использует вариант SynthID-Text: сигнал образуется при выборе токенов, а не за счёт скрытых символов. На дату проверки, 16 сентября 2026 года, официальный детектор описан как private preview. Точный рабочий профиль Claude в исследованных открытых источниках не найден. Поэтому результат нашего демонстрационного детектора нельзя переносить на Claude.

## Запуск

Python 3.9 или новее; для самого приложения дополнительные библиотеки не нужны.

```sh
git clone https://github.com/kadyrbekovhamit-cyber/watermark-lab.git
cd watermark-lab
python3 -B server.py --port 4548
```

Открыть <http://127.0.0.1:4548>. Сервер слушает только этот компьютер. Остановка — Ctrl+C в его терминале. Приложение не обращается к моделям и внешним API, не загружает шрифты, не воспроизводит звук. После запуска интернет не требуется. Ссылки на источники открываются только при нажатии.

Три режима:

1. **Ваш текст.** Показывает объём и специальные Unicode-символы; сохраняет статус метки Claude «недоступно». Unicode-символы не являются свидетельством AI-авторства.
2. **Контрольный эксперимент.** Пересчитывает три сохранённых примера: метка с известным ключом, отсутствие метки, метка другого ключа. Это искусственные токены нашего генератора, не ответы Claude.
3. **Известный профиль.** Проверяет импортированные идентификаторы токенов по совместимым ключам и настройкам. Без сопоставимой калибровки показывает только балл.

Исходный текст и переданные ключи не записываются сервером в файлы или журналы. Они обрабатываются в памяти. Кнопка скачивания сохраняет отчёт по явному действию пользователя. Отчёт по токенам содержит до 256 идентификаторов из входа; отчёт по тексту — его SHA-256 и позиции специальных символов. Не считайте экспорт автоматически анонимным. Браузер и операционная система управляют своей памятью отдельно от приложения.

## Командная строка и формат

```sh
python3 -B watermark_lab.py text document.txt
python3 -B watermark_lab.py tokens evidence/demo-marked_correct_key.json
```

Команда выводит JSON в терминал. Интерфейс и CLI принимают как объект ниже, так и сохранённый демонстрационный файл, где он вложен в `payload`:

```json
{
  "token_ids": [10, 32, 45, 78, 12],
  "tokenizer_id": "synthetic-uniform-1024-v1",
  "profile": {
    "algorithm": "deepmind-synthid-addb4a15-int64-le-v1",
    "keys": [17, 263, 1021, 4099, 8191, 16381, 32749, 65521],
    "ngram_len": 5,
    "context_history_size": 1024,
    "tokenizer_id": "synthetic-uniform-1024-v1"
  }
}
```

Пять токенов в этом коротком примере недостаточны для заключения. Полный рабочий пример с калибровкой — `evidence/demo-marked_correct_key.json`. Максимум: 4096 токенов, 100 000 символов текста, 512 000 байт входного файла/HTTP-запроса. `eos_token_id` необязателен: он и всё после его первого появления исключаются.

Нужны **реальные ID токенов именно того генератора**, который использовал указанный профиль. Разбиение русского или английского текста на слова не заменяет его токенизатор. Имя `tokenizer_id` проверяет согласованность заявления, но не удостоверяет, что переданные ID действительно получены этим токенизатором.

Калибровка содержит `profile_fingerprint`, `tokenizer_id`, `input_tokens`, `scored_contexts`, `null_scores` и описание `population`. Форма видна в `evidence/demo-calibration.json`. Контрольные образцы должны быть независимыми от проверяемого образца, без исследуемой метки и представлять тот же источник данных. Их происхождение программа самостоятельно не проверяет. Демонстрационная калибровка применима только к её синтетической популяции.

## Что измерено

Зафиксированы код, порог 0,01, диапазоны seed и отдельная калибровка из 199 образцов. Отложенная проверка: 300 последовательностей по 128 искусственных токенов, 124 учитываемых контекста, 8 ключей.

| Отложенная группа | Образцов | Обнаружен сигнал проверяемого профиля |
| --- | ---: | ---: |
| Метка известного ключа | 100 | 100 |
| Без метки | 100 | **1 ложное срабатывание** |
| Метка другого ключа | 100 | 0 |

Это наблюдения в ограниченном синтетическом опыте, **не оценка точности на естественном языке или Claude**. Отрицательный результат с чужим ключом не означает отсутствия всякой метки.

Арифметика хеширования и g-оценок совпала с 2072 двоичными результатами закреплённого кода DeepMind; проверено и маскированное среднее. Проверка исполняет тела трёх исходных функций через небольшой NumPy-адаптер, а не весь стек PyTorch и не модель. Исходный код и контрольные суммы сохранены в `reference/SOURCE_LOCK.json`; лицензия и изменения описаны в `NOTICE`.

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 python3 -B -m unittest -v test_watermark_lab.py
```

Для теста сравнения и повторного исследования нужен установленный NumPy. Полный синтетический опыт повторяется командой `python3 -B validate.py`; вычисления выполняются последовательно. Сырые результаты всех 300 образцов — `evidence/benchmark.json`, журнал тестов — `evidence/unit-tests.log`.

## Следующий исследовательский шаг

Для настоящей проверки Claude необходим совместимый подтверждённый профиль либо доступ к официальному детектору. Альтернатива — отдельное исследование детекции без ключа на корпусе исходных ответов с известными моделью, датой, условиями генерации и сопоставимыми контрольными текстами. Такой эксперимент мог бы выявить корреляцию, но не доказал бы расшифровку метки без дополнительной проверки.

Доступ к закрытому API не запрашивался; платные вызовы не выполнялись. Технический разбор — [ALGORITHM.ru.md](ALGORITHM.ru.md). Результат поиска ключа — [KEY_SEARCH.md](KEY_SEARCH.md).
