# Можно ли найти закономерность по тысячам ответов?

**Результат на 16 сентября 2026:** программа научилась различать некоторые
синтетические выборки, получая только частоты ответов. Ключ генератора ей не
передавался. **Секретный ключ не восстановлен; настоящих ответов Claude в опыте нет.**

Идея пользователя проверена в ограниченной форме: если после одного контекста
генератор чаще выбирает определённое продолжение, можно ли научиться узнавать
это предпочтение по наблюдениям?

## Как устроен опыт

Есть 32 искусственных контекста и четыре возможных продолжения. Один ответ —
выбор одного искусственного токена. Это не статья, не полноценная языковая модель
и не тысячи настоящих переписок.

Для каждого контекста собраны ответы исследуемого генератора и сопоставимого
контроля. Обучение использует два префикса, проверка — два других. Базовые
вероятности выбора зависят от префикса. Контексты при этом уже знакомы программе:
она запоминает отношения частот для каждого контекста и продолжения.

В максимальном варианте обучение получает 16 384 наблюдения: 8 192 исследуемых
и 8 192 контрольных. Проверка использует отдельные 32 768 наблюдений на сценарий.
Ключи и промежуточные значения алгоритма метки доступны только генератору,
обучающаяся часть их не получает.

## Что получилось

Точность здесь — доля правильно различённых **одиночных искусственных выборов**
из двух равных групп. Это не процент распознавания Claude или авторства статьи.

| Обучающих наблюдений, обе группы | Открытая схема метки | Одинаковые распределения без метки | Обычное предпочтение без метки |
| ---: | ---: | ---: | ---: |
| 1 024 | 68,45% | 50,33% | 62,09% |
| 4 096 | 70,88% | 49,81% | 65,74% |
| 16 384 | 71,20% | 49,87% | 66,85% |

В первом сценарии использована закреплённая открытая реализация арифметики
SynthID. Во втором исследуемая и контрольная группы устроены одинаково.
В третьем одно продолжение получает увеличенный в пять раз вес — **без какого-либо
ключа метки**. Программа замечает и это обычное предпочтение.

Поэтому сочетания слов действительно могут содержать закономерность, но сама
закономерность не доказывает ни наличие водяного знака, ни восстановление ключа.
На неизвестных контекстах этот метод вообще воздерживается от ответа.

Все девять запусков сохранены; неудачные результаты не отбрасывались. Проверочная
выборка повторно используется только для описания роста точности при трёх объёмах
обучения. Статистический тест сообщается лишь для заранее выбранного максимального
объёма: p=0,000244; 0,718018; 0,000244 соответственно. Он проверяет различие
распределений, а не происхождение метки. Один контрольный запуск не позволяет
оценить общую частоту ложных срабатываний.

Тест предполагает независимость проверочных ячеек и возможность переставлять
метки двух групп внутри каждой ячейки при отсутствии различий. Происхождение
данных и выполнение этих предположений программа по JSON проверить не может.
Подробная методика: [английское описание](PREFERENCE_LEARNING.md).

## Как повторить

Нужен Python 3.9+. Этот модуль запускается из терминала; в браузерный интерфейс
он пока не добавлен. Интернет, ключ API и загрузка модели не нужны.

```sh
python3 -B preference_probe.py benchmark \
  --output private/preference-benchmark.json \
  --fixture private/preference-corpus-synthetic.json

python3 -B preference_probe.py analyze \
  private/preference-corpus-synthetic.json \
  --output private/preference-result.json
```

Команды записывают результаты в указанные файлы; существующий выходной файл может
быть заменён. `private/` исключена из Git. В опубликованном примере только
синтетические данные: [корпус](evidence/preference-corpus-synthetic.json) и
[все результаты](evidence/preference-benchmark.json).

Для собственного опыта нужен корпус формата `conditional-choice-corpus-v1`:
постоянный список вариантов `choices`, декларация `provenance.kind`, массивы
`training` и `validation`. Каждая строка содержит идентификаторы `context`,
`prefix`, группу `target` или `control` и массив целых частот `counts`.
В каждой ячейке нужны обе группы равного размера; префиксы обучения и проверки
не должны пересекаться. Полный рабочий пример — по ссылке выше.

## Что нужно для следующего шага

Тысячи случайных ответов Claude сами по себе не дают сопоставимых повторов и
контроля. Нужны зафиксированные модель, версия, дата, условия генерации,
независимая проверка и учёт всех исходов. Человеческий текст или ответы другой
модели не становятся подходящим контролем автоматически.

Сначала предусмотрен [малый пилот](PROBE_PROTOCOL.md), проверяющий формат и
разнообразие. Большой сбор пока не выполнялся. В отчёте остаются
`claude_status: unavailable` и `key_recovered: false`.

Исследования [ICML 2024](https://proceedings.mlr.press/v235/jovanovic24a.html) и
[ETH Zürich](https://www.sri.inf.ethz.ch/blog/probingsynthid) показывают подходы к
изучению предпочтений метки без знания ключа. Этот небольшой опыт не является
повторением их исследований и не переносит их результаты на Claude.
