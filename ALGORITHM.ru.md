# Что мы разобрали в «метке в словах»

Проверено 16 сентября 2026 года. Описанный ниже точный расчёт относится к [открытой реализации DeepMind](https://github.com/google-deepmind/synthid-text/tree/addb4a158143c7c6851a1308f78b89fceed59683), commit `addb4a158143c7c6851a1308f78b89fceed59683`. Он не объявляется точной конфигурацией Claude.

## Принцип

Генератор выбирает следующий токен из распределения вероятностей. Ключ вместе с несколькими предшествующими токенами задаёт для каждого варианта последовательность битов `g = 0/1`. Генератор сдвигает выбор в пользу определённых битов. Детектор, имеющий тот же профиль, пересчитывает их для готовой последовательности и ищет избыток единиц.

Отдельное слово не имеет постоянной «метки Claude»: его оценка зависит от контекста, токенизации и ключа. Переносы, тире и невидимые символы не раскрывают этот статистический сигнал. Связь Claude с вариантом SynthID-Text и статус официального доступа описаны [Anthropic](https://www.anthropic.com/news/claude-text-watermark).

## Точная арифметика поддерживаемого профиля

Профиль включает длину окна `n`, упорядоченный набор `d` ключей, размер истории контекстов и идентификатор токенизатора. Наш адаптер явно фиксирует little-endian сериализацию signed int64 ключей. Смешивание далее использует переполнение signed int64.

1. Начальное значение: `IV = int(SHA256(int64_le(keys)), big_endian) mod (2^63 − 1)`.
2. Для каждого ID в окне из `n` токенов: `h = int64((h + token) × 6364136223846793005 + 1)`, начиная с IV.
3. Для каждого ключа выполняется ещё один такой шаг с ключом вместо токена.
4. Затем 12 раз: `h = int64((h + 1) × 6364136223846793005 + 1) >> 5`, с арифметическим сдвигом вправо.
5. Бит слоя: `g = (h >> 30) mod 2`.

Это перенос конкретного публичного кода. Более ранние интеграции SynthID с sampling table могут использовать другую арифметику. Само название SynthID не гарантирует совместимость.

## Встраивание в демонстрационном генераторе

Для одного слоя, токенов `i`, исходных вероятностей `p_i` и соответствующих битов `g_i`:

```text
m = Σ p_i g_i
p'_i = p_i (1 + g_i − m)
```

Обновление повторяется по слоям. При нормированных неотрицательных вероятностях оно сохраняет сумму 1 и не создаёт отрицательных значений. Если возможен только один токен, перераспределять вероятность некуда. Это объясняет, почему мало вариативный текст может нести слабый сигнал; характеристики реальных моделей здесь не измерены.

В нашем опыте на каждом шаге случайно выбираются 16 кандидатов из словаря 1024 целых ID. После восьми обновлений берётся случайный токен из получившегося распределения. Первые четыре токена — случайный контекст. Это небольшой имитатор, не языковая модель. В этих фиксированных примерах повторных четырёхтокенных контекстов нет; общий механизм пропуска повторов генератора не моделировался.

## Детекция

Первые `n−1` токенов не оцениваются. Контекстом для токена считается предшествующее окно длины `n−1`. Если его хеш уже встречался в ограниченной истории, оценка исключается. История и её начальное заполнение нулями повторяют выбранный исходный код. Исключаются EOS и последующие токены, если указан EOS ID.

```text
S = Σ_t Σ_l mask_t × g_t,l / (d × Σ_t mask_t)
```

Здесь `S` — средний g-балл; это **не вероятность авторства**. Удаление повторов не делает перекрывающиеся окна независимыми. Поэтому приложение не выдаёт универсальный p-value по предположению независимости отдельных битов.

Наше правило заключения использует эмпирический ранг относительно отдельной контрольной выборки из `M` последовательностей:

```text
r = (1 + число контрольных S_j ≥ S) / (M + 1)
сигнал профиля обнаружен, если r ≤ 0,01
```

Поправка +1 исключает нулевой ранг, совпадения учитываются консервативно. Такая интерпретация требует сопоставимости контрольной и исследуемой популяций, заранее фиксированного профиля и одиночной проверки. Перебор ключей, множества фрагментов или порогов требует отдельного учёта множественных проверок. Совпадение полей JSON не подтверждает эти статистические предпосылки.

Минимум 64 учитываемых контекста и 99 контрольных оценок — ограничения этого приложения, а не требования Anthropic. При недостающей или несовпадающей калибровке результат остаётся без заключения.

## Что остаётся неизвестным

Не получены ключи Claude, точная токенизация и параметры его развёрнутой схемы. Публичная совместимость нашего расчёта с одним снимком DeepMind не восполняет их отсутствие. Поле `claude_status` всегда остаётся `unavailable`, независимо от демонстрационного результата.

Проверка нового неизвестного текста по демонстрационным ключам ответила бы лишь на вопрос о сигнале этих ключей. Чтобы обнаруживать конкретную закрытую метку, требуется дополнительная подтверждённая информация или отдельное валидированное исследование. Стилистический классификатор не был бы автоматически детектором этой метки.
